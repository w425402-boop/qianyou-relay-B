## 1. 你这一棒交付什么

**为什么拆给你**：推荐是独立算法（权重公式），输入只有活动数据和当前用户，输出前 3 名和附近列表；适合单独考算法落地。

逐条交付，不许减项：

1. 实现 `QY.recommendScore(activity, user)`，公式**写死**：`score = 兴趣匹配×40 + 距离分×30 + 热度分×30`。其中 兴趣匹配＝`tags` 与 `interests` 交集数 ÷ `interests` 总数；距离分＝`1 - distance/50`（超 50 按 0 计）；热度分＝`joined/capacity`。
2. **"今日最佳"区**：取推荐分前 3 名展示，区块标题固定为"今日最佳"；按最高得分维度选一句话理由模板：`你关注了{兴趣}` / `离你仅{distance}km` / `已有{joined}人报名`。
3. **"附近"区**：按 `distance` 升序排列，显示距离（"1.2km"格式）。
4. 实现 `QY.topRecommendations(n)` 返回前 n 名，供 check.js 调用。

**交付物**：`js/modules/recommend.js`；`tests/check.js` 里追加 2 条断言（同种子算两次前 3 名不变；抽查一条手算推荐分一致）；《交接单》。

## 2. 契约前置（先看契约再写代码，10 分钟）

对照 CONTRACT.md 第 4 节，本棒 3 个对外函数：

| 函数 | 入参 | 返回值 | 出错行为 |
| :--- | :--- | :--- | :--- |
| `QY.recommendScore(activity, user)` | `activity: Activity`、`user: User` | `number`，0–100 的推荐分（不许返回字符串） | 参数缺失 → `0`，不抛 |
| `QY.topRecommendations(n)` | `n: number` | 按分数降序的 `Activity[]`，长度 ≤ n | `n` 缺省 → 3；`n` 超总数 → 全部 |

**只许改（owns）**：`js/modules/recommend.js`
**只许追加（appendOnly）**：`css/style.css`（只追加 M3 区块）、`tests/check.js`（只追加 M3 断言）

## 3. 定桩说明（本棒要摘掉的桩）

开局三个函数是 `QY.seam.stub('M3 QY.recommendScore')` 形态，一调用即抛 `[SEAM 未实现]`。

**交付标准**：M3 的 3 个契约函数全部不再是桩，`node tests/contract.js` 的「本棒模块仍是桩」检查转绿。

```js
// js/modules/recommend.js —— 从桩到真实现
(function (root) {
  var QY = (root.QY = root.QY || {});
  var W = { interest: 40, distance: 30, hot: 30 };     // 权重写死，找到这三个数字是评分点

  // 三因子拆开算：便于"按最高维度选理由"复用同一份中间值
  function factors(act, user) {
    var iv = Array.isArray(user && user.interests) ? user.interests : [];
    var tg = Array.isArray(act && act.tags) ? act.tags : [];
    var hit = 0;
    for (var i = 0; i < iv.length; i++) if (tg.indexOf(iv[i]) > -1) hit++;
    return {
      interest: iv.length ? hit / iv.length : 0,             // 交集÷兴趣总数
      distance: act.distance <= 50 ? 1 - act.distance / 50 : 0,
      hot: act.capacity > 0 ? act.joined / act.capacity : 0
    };
  }

  // 契约函数：纯函数，不读 store，check.js 会直接喂数据
  QY.recommendScore = function (act, user) {
    if (!act || !user) return 0;
    var f = factors(act, user);
    return f.interest * W.interest + f.distance * W.distance + f.hot * W.hot;
  };

  // 契约函数：前 n 名，返回活动对象（不是包装对象）
  QY.topRecommendations = function (n) {
    var me = QY.store.getUser('u01');
    return (QY.store.load().activities || [])
      .map(function (a) { return { a: a, s: QY.recommendScore(a, me) }; })
      .sort(function (x, y) { return y.s - x.s || (x.a.id < y.a.id ? -1 : 1); })
      .slice(0, n == null ? 3 : n)
      .map(function (r) { return r.a; });
  };

  // 渲染：#recommend-slot 内两块；附近单独按 distance 升序排
  QY.renderRecommend = function () { /* 今日最佳 Top3 + 附近列表（"1.2km" 格式） */ };
})(typeof window !== 'undefined' ? window : globalThis);
```

一个坑：理由模板按"最高得分维度"选——三因子各自已加权，比较 `f.interest*40` / `f.distance*30` / `f.hot*30` 三者大小，别比较未加权的原始比例，否则说的理由和分数对不上。
