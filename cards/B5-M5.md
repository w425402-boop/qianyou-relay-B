## 1. 你这一棒交付什么

**为什么拆给你**：考察多字段表单逐项校验、30 秒自动草稿持久化，以及与发现页列表的跨模块契约联动。

逐条交付，不许减项：

1. 发起表单 **7 个字段**：标题、分类（下拉 6 类必选）、时间、地点、费用、人数上限、描述。
2. **提交校验**（不过就标红该字段并提示）：标题必填 2–20 字；分类必选；时间必填且晚于现在（否则提示"时间须晚于现在"）；地点必填；费用数字 ≥ 0；人数上限整数 2–50；描述选填 ≤ 200 字。
3. **草稿**：填表过程**每 30 秒自动保存一次**＋"保存草稿"手动按钮，存 `store.draft`；刷新后提示"恢复上次草稿？"，点确认恢复。
4. **发布**：新活动 `id` 为 `a`＋时间戳，`status` 为 `ongoing`，`joined` 为 0，`hostId` 为 `u01`；发布后跳新活动详情页（`#/detail/:id`），回到发现页列表条数＋1。

**交付物**：`js/modules/publish.js`；`tests/check.js` 里追加 2 条断言（校验函数对非法返回假、对合法返回真）；《交接单》。

## 2. 契约前置（先看契约再写代码，10 分钟）

对照 CONTRACT.md 第 4 节，本棒 2 个对外函数：

| 函数 | 入参 | 返回值 | 出错行为 |
| :--- | :--- | :--- | :--- |
| `QY.renderPublish()` | 无 | 渲染 7 字段表单＋保存草稿按钮，返回 `undefined` | 容器不存在 → 静默返回 |
| `QY.validatePublish(fields)` | `Object`（7 字段原始值，多为字符串） | `boolean`：全合法 `true`，任一不合法 `false` | 入参缺失 → `false`，不抛；**不许返回错误对象** |

标红定位用你自己加的 `QY.validatePublishDetailed(fields)` → `{ valid, errors: { field: msg } }`。契约函数只负责布尔，check.js 按布尔断言。

草稿结构（写进 `store.draft`）：
```js
// 落库时的形状
state.draft = { title, category, time, place, cost, capacity, desc, savedAt: '2026-11-25T10:00:00.000Z' };
```

**只许改（owns）**：`js/modules/publish.js`
**只许追加（appendOnly）**：`css/style.css`（只追加 M5 区块）、`tests/check.js`（只追加 M5 断言）
**不属于你**：`js/router.js`（M1 owns）、`js/modules/discover.js`（M2 owns）—— 列表条数＋1 靠 M2 重渲染，你只负责写库后跳 `#/detail/:id`

红线：**不遵守就是契约违规，扣 3 分/条。**

## 3. 定桩说明（本棒要摘掉的桩）

开局两个函数是 `QY.seam.stub('M5 QY.renderPublish')` 形态，一调用即抛 `[SEAM 未实现]`。

**交付标准**：M5 的 2 个契约函数全部不再是桩，`node tests/contract.js` 的「本棒模块仍是桩」检查转绿。

```js
// js/modules/publish.js —— 从桩到真实现（草稿这块最容易翻车）
(function (root) {
  var QY = (root.QY = root.QY || {});
  var CATS = ['美食', '咖啡', '桌游', '运动', '文娱', '户外'];
  var timer = null;

  // 契约函数：布尔，逐条规则全部命中才 true
  QY.validatePublish = function (fields) {
    var f = fields || {};
    var title = String(f.title == null ? '' : f.title).trim();
    if (title.length < 2 || title.length > 20) return false;              // 标题 2–20 字
    if (CATS.indexOf(f.category) === -1) return false;                    // 分类必选
    var t = new Date(f.time).getTime();
    if (!f.time || isNaN(t) || t <= Date.now()) return false;             // 必须晚于现在
    if (!String(f.place == null ? '' : f.place).trim()) return false;     // 地点必填
    var cost = Number(f.cost);
    if (f.cost === '' || isNaN(cost) || cost < 0) return false;           // 费用 ≥ 0
    var cap = Number(f.capacity);
    if (!(Math.floor(cap) === cap && cap >= 2 && cap <= 50)) return false;// 2–50 整数
    if (String(f.desc == null ? '' : f.desc).length > 200) return false;  // 描述 ≤ 200
    return true;
  };

  // 草稿：30 秒自动 + 手动按钮；离开页面必须清定时器，否则跳详情后还在写库
  function startAutoDraft(readFormFn) {
    if (timer) clearInterval(timer);
    timer = setInterval(function () {
      var state = QY.store.load(); state.draft = Object.assign(readFormFn(), { savedAt: new Date().toISOString() });
      QY.store.save(state);
    }, 30000);                                                            // 契约要求的 30 秒
  }

  // 发布：写库 → 清草稿 → 跳详情。id 用 a+时间戳，joined 必须 0
  QY.publishActivity = function (fields) {
    if (!QY.validatePublish(fields)) return null;                         // 校验不过绝不写库
    var state = QY.store.load();
    var id = 'a' + Date.now();
    state.activities.push({
      id: id, title: fields.title.trim(), category: fields.category, desc: fields.desc || '',
      time: new Date(fields.time).toISOString(), place: fields.place.trim(),
      cost: Number(fields.cost), capacity: Number(fields.capacity), joined: 0, signedUserIds: [],
      hostId: 'u01', status: 'ongoing', distance: 0, tags: [fields.category]
    });
    state.draft = null; QY.store.save(state);                             // 发布成功即清草稿
    if (timer) clearInterval(timer);
    location.hash = '#/detail/' + id;
    return id;
  };
  QY.renderPublish = function () { /* 7 字段表单 + 保存草稿按钮 + 恢复草稿提示条 */ };
})(typeof window !== 'undefined' ? window : globalThis);
```

三个坑：①恢复提示不能是 `alert`（契约禁用阻塞弹窗），用页面内提示条 + "恢复"/"不恢复"两个按钮；②"时间须晚于现在"这句文案必须逐字一致，验收清单按字核；③`capacity`、`cost` 存进活动时转 `Number`，留字符串会让 M4 的满员判断静默失效。

## 5. 自测闸门（不过不许提 PR）

**闸门一 功能**：`node tests/check.js` 输出全 PASS（别人的桩 SKIP 不算失败，M5 的断言必须 PASS 不能 SKIP）。Q5 验收清单逐条自检：

☐ 空标题提交被拦，标题字段标红
☐ 时间填过去被拦，提示"时间须晚于现在"
☐ 人数填 51 被拦；费用填 -5 被拦
☐ 发布一条新活动，发现列表条数＋1，详情页打得开
☐ 填一半刷新，点"恢复上次草稿"能恢复

**闸门二 契约**：`node tests/contract.js` 零违规 —— 越界（碰 M1/M2/M4 文件都算）、缺函数（2 个少一个）、localStorage 泄漏（你的文件里出现 `localStorage` 直接红）三类全绿。

**闸门三 浏览器**：页面 0 控制台报错；发布后刷新，新活动仍在、草稿已清空。

三条全绿才能 `git push`，否则 PR 上的 GitHub Actions 会自动红，当场打回。

## 7. 前面人答不出来，你怎么办（降级接力）

- **正常**：B1–B4 已合并进 main → `git pull origin main` 直接开工。
- **L1 上一棒超时未交付**：老师已在 main 打 `wip/b4` 标签（半成品合入，允许 TODO，闸门必须绿）→ 照常从 main 拉，交接单写 `INHERITED: B4 未完成项 = <逐条列出>`。详情页没接完不影响发布页；发布后跳详情若渲染是桩，用自己的"发布成功"提示兜住并记一条。
- **L2 上一棒提交的代码闸门红**：老师把 main 回退到 `seam/b5-start` 快照（= 开工前的纯定桩状态）→ 你**从定桩开工**，上游模块保持桩状态（`[SEAM 未实现]` 是合法的），你的模块照做，不受影响。"发现列表条数＋1"这条验收在 M2 是桩时无法走页面验证——改用 `store.load().activities.length` 直接断言，并在交接单说明验证口径。
- **L3 上一棒彻底没来**：main 就是纯定桩 → 你照常开工，同上。

**关键认知：因为出题方预置了定桩，你的开工永远不被上游卡住。** 上游是桩、你的下游也是桩，接口在、签名在，你能跑自己的测试。你唯一不能被豁免的是自己模块的交付。
