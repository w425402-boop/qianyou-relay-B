# 牵友接力面试 · 定桩骨架仓库

> 这是「牵友」线下组局社交 App 的**接力开发面试**工程。
> 15 人分两组（A 组 7 人、B 组 8 人），每人 50 分钟做一个模块，串行接力，一天内跑通完整产品。

---

## 先读这三句

1. **你不是从零写代码**，是读懂契约、按接口补齐一个模块。仓库里已经有一整套签名齐全的骨架。
2. **上游没交付不影响你开工**。缺的模块只差「花括号里有没有东西」，接口位置全在。
3. **两道闸门管着你的交付**：功能闸门 + 契约闸门，GitHub Actions 会自动挡 PR，过不去点不了 Merge。

---

## 开局三步（5 分钟，做不完不许开工）

```bash
git clone <本仓库地址> && cd qianyou-relay-<你的组>
git checkout -b seat/<你的座位>-<你的模块>     # 例：seat/a3-m3
node tests/check.js                            # 看桩状态仪表盘
node tests/contract.js                         # 契约闸门，开局应该是绿的
```

第三条命令会打印一张进度表：

```
[SKIP] M2 QY.renderDiscover —— 桩未实现
[SKIP] M3 QY.recommendScore —— 桩未实现
...
契约函数：已实现 4 / 30 · 仍是桩 26 · 缺失 0 · 进度 13%
```

你负责的模块现在一定在 `[SKIP]` 里。**交付时它必须变成 `[PASS]`。**

浏览器里双击 `index.html`（或 `npx serve`）也能看：右上角点「桩状态」，30 个函数逐个标颜色，哪些还没人做一目了然。

## 两道闸门

### 闸门一 · 功能 `node tests/check.js`
- 跨棒累积的纯 Node 断言，每棒只许往**末尾追加**自己模块那一段
- 桩状态输出 `[SKIP]` 不算失败；但**你自己模块的断言必须 `[PASS]`**
- 末尾打印全项目 `real / stub / missing` 仪表盘

### 闸门二 · 契约 `node tests/contract.js`
三类硬检查，任一红就 fail：

| 检查 | 抓什么 |
| :--- | :--- |
| 文件越界 | 改了 `OWNERS.json` 里不属于你的文件 → 直接报「越界修改：`js/store.js` —— 属于 A1，本棒 A3 无权修改」 |
| 契约完整性 | 30 条 `QY.*` 缺一条就 FAIL；本棒模块交付时仍是桩也 FAIL |
| 代码卫生 | 除 `js/store.js` 外出现 `localStorage` 字样 → FAIL；出现 `alert(` / `confirm(` → FAIL |

```bash
node tests/contract.js origin/main A3     # 参数：基准分支、你的座位号
```

## 提 PR 前必须全绿

```bash
node tests/check.js          # 我的模块断言 PASS，没有 FAIL
node tests/contract.js       # 零违规
git add -A && git commit -m "test(mN): [45m] ..."
git push -u origin seat/<座位>-<模块>
gh pr create --base main --title "<座位> <模块> <模块名>"
```

PR 上会自动跑 GitHub Actions（`.github/workflows/gate.yml`），两条闸门都绿才允许 Merge。红了当场打回，计时不停。

**别忘了填 `handovers/<座位>-handover.md`** 并随 PR 提交——那是你交给下一棒的东西，也是评分的直接证据。

## 上游没交付怎么办（三级降级）

这是本仓库设计里最关键的一条。**你永远不会因为上游卡死而停摆。**

| 级别 | 情况 | 你怎么做 |
| :--- | :--- | :--- |
| **L0 正常** | 上一棒已合并进 `main` | `git pull origin main`，照常开工 |
| **L1 超时收编** | 上一棒超时，但已有可用 commit，老师打了 `wip/a<N-1>` tag | 照常从 `main` 拉；交接单里写 `INHERITED: A<N-1> 未完成项 = …` |
| **L2 闸门红回退** | 上一棒 PR 双闸门红，15 分钟内修不好 | 老师把 `main` 保持在起点快照 `seam/a<N>-start`（纯定桩）。你 `git checkout -b seat/… seam/a<N>-start` 从**纯定桩**开工。上游模块保持 `[SEAM 未实现]` 是**合法状态**，不用管它 |
| **L3 缺席** | 该棒没人来 | 等同 L2，你照常开工 |

**为什么能这样**：因为 30 个契约函数的位置全在，缺的只是「那个花括号里有没有实现」。上游是桩，你的下游也是桩，接口在、签名在、你能跑自己的测试。

**救援加分**：若你顺手把上游遗留模块补齐了（且双闸门绿），个人分 +5。但不许因此超时。

---

## 四条红线（碰了直接扣分或 0 分）

1. **只改自己 `owns` 的文件**。改别人的 → 契约闸门红，−3 分/条。
2. **不许改冻结文件**：`CONTRACT.md` / `OWNERS.json` / `js/seam.js` / `js/boot.js` / `tests/contract.js` / `.github/workflows/gate.yml` → 该模块记 0。
3. **不许直推 `main`，不许 `force push`**。分支保护会拒，操作失败且计时不停。
4. **不许把下游已实现的函数回退成桩**。回退等于让下游重新断供 → −10 分。

## 评审怎么评

每人做完不离场，留任下一棒的评审员。**只挑四类毛病**：

1. 违反契约（改他人文件 / 私改字段 / 碰 `localStorage`）
2. 闸门没过（脚本报错 / 控制台红字 / 刷新丢数据）
3. 接口对不上（`QY.*` 函数名、参数、路由与契约不符）
4. 交接单没写清（改动 / TODO / 下游注意事项缺失）

代码风格、命名喜好**不算毛病**。每条有效毛病：被评审人 −3 分，评审人 +2 分。评审走过场（一条没发现但老师发现了）→ 交接质量 −5 分。

## 找谁

| 问题 | 找 |
| :--- | :--- |
| 环境跑不起来 | 老师，当场换备用机，不停表 |
| 契约看不懂 | 先读 `CONTRACT.md` 第 4 节函数表；仍不清楚再问，问的时候说清是哪一条 |
| 上游代码有问题 | **记到交接单的 `INHERITED:` 里，别自己改人家文件** |
| 闸门红了看不懂 | 看报错里的文件名和行号；`tests/contract.js` 的报错会直接告诉你归谁 |
